# Часто задаваемые вопросы (FAQ)

> ⚙️ **Рабочий документ** — может уточняться и дополняться по мере развития проекта.

## О портале

### Что показывает индекс зрелости?
Комплексная оценка качества системы IC.TP по 6 измерениям (каждое 0-10). Итоговое значение — средний балл. Например, если все измерения по 6.2, то индекс = 6.2.

### Как часто обновляются данные портала?
- **KPI и метрики** — каждые 30 минут через GitHub Actions
- **Решения и рефлексии** — после добавления в `data/portal.json`
- **Участники и задачи** — синхронизируются из GitHub Issues

### Почему показатель Связности низкий?
Связность (0-100) считается по 6 факторам. Для повышения нужно:
1. Улучшить документацию (README, GLOSSARY, FAQ) ✓
2. Создать граф знаний (KNOWLEDGE_GRAPH.md)
3. Исправить нарушения Стража (Guardian violations)
4. Ускорить Code Review процесс
5. Обновить документы ≤30 дней

## О KPI

### Что такое "Участников"?
Количество активных членов команды IC.TP. Считается из массива участников в `data/portal.json`.

### Что означает "Открытых задач"?
Количество активных Issues в GitHub репо. Показывает объем работы в процессе.

### Как считается "До следующего Milestone"?
Разница в днях от сегодня до даты ближайшего Milestone с статусом `pending` или `active`.

## О дорожной карте

### Что такое Milestone?
Контрольная точка проекта с конкретной датой и целями. Примеры:
- "Онбординг ЦИРа" (завершен)
- "Рамка готова" (активный)
- "Сценарий онбординга" (следующий)

### Как Milestone переходит в статус "done"?
Когда достигнуты все цели Milestone и Issues закрыты, обновляется статус в `data/portal.json`.

## О решениях и рефлексии

### В чем разница между Решениями и Рефлексией?
- **Решения** — протоколы синхронизационных встреч, формальные решения (Архив)
- **Рефлексия** — диалоги о развитии позиций, вопросы и инсайты (Актуально)

### Почему Решения помечены как "Архив"?
Потому что последняя встреча была 15.06.2026, и требуется протокол новой встречи с актуальными решениями.

### Кто может быть модератором рефлексии?
Обычно опытный член команды. Текущий модератор — Денис Рудоманенко.

## О Связности системы

### Как считается "Документирование"?
**Идеал (100 баллов):**
- README/CONTRIBUTING/ONBOARDING/ARCHITECTURE (+60)
- GLOSSARY — словарь сущностей (+15)
- Граф знаний в main (+15)
- Свежесть docs ≤30 дней (+10)

### Как считается "Управление знаниями"?
**Идеал (100 баллов):**
- decisions/insights/CHANGELOG/examples (+45)
- папки рефлексий ≥3 (+10)
- свежая рефлексия ≤7 дней (+15)
- decisions.md ≤14 дней (+10)
- FAQ (+10)

### Почему "Дисциплина разработки" показывает нарушения?
Страж автоматически выявляет нарушения гигиены репо (структура файлов, метаданные, правила PR). Каждое нарушение = -10 баллов к Связности.

## О Страже

### Что делает Страж?
Монитор гигиены репо, который проверяет:
- Структуру файлов и папок
- Соответствие метаданных
- Правила в Pull Requests
- Версионирование артефактов

### Какие Фазы Стража?
- Phase 1 (готова): Гигиена файлов
- Phase 2 (разработка): Scope Monitor с Telegram уведомлениями
- Phase 3-5 (планируются): Smart Rules и Self-Healing

## О команде

### Как добавить нового участника?
1. Добавить в массив `participants` в `data/portal.json`
2. Указать роль, экспертизу, GitHub аккаунт
3. Назначить первые задачи
4. Портал обновится в течение минуты

### Что такое "Белбин роли"?
Классификация ролей в команде (9 архетипов). Используется для понимания раскладки в IC.TP.

## О развитии портала

### Как предложить улучшение портала?
1. Создать Issue в репо ic-tp-portal
2. Описать идею и почему она нужна
3. Обсудить с командой на встречах

### Как портал разворачивается?
- **Frontend** (HTML/JS) — на Vercel CDN
- **Data** — JSON файлы в репо
- **API** — Vercel serverless functions
- **Metrics** — автоматизация через GitHub Actions
