# Словарь сущностей IC.TP Portal

> ⚙️ **Рабочий документ** — может уточняться и дополняться по мере развития проекта.

## Ключевые сущности

### Портал (Portal)
Веб-интерфейс для визуализации состояния проекта IC.TP. Показывает KPI, дорожную карту, решения, рефлексии, участников и инструменты.

### KPI (Key Performance Indicators)
Ключевые показатели производительности:
- **Участников** — численность активной команды (текущее значение: 5)
- **Открытых задач** — количество активных Issues в репо (текущее: 15)
- **Индекс зрелости** — комплексная оценка качества системы по 6 измерениям (0-10 шкала)
- **До следующего Milestone** — дней до ближайшей контрольной точки

### Дорожная карта (Roadmap)
Последовательность контрольных точек и целей проекта. Каждый Milestone имеет:
- Название и дату
- Статус: `done` (завершен), `active` (идет), `pending` (предстоит)
- Badge для визуализации

### Решения встречи (Decisions)
Протоколы решений, принятых на синхронизационных встречах. Содержит:
- Код решения (А-1, О-2 и т.д.)
- Текст решения
- Дата встречи

### Рефлексия (Reflection)
Сессии рефлексии команды — диалоги о развитии позиций, понимании и видении. Включают:
- Дата сессии
- Модератор
- Участники
- Вопросы и инсайты

### Участники (Participants)
Члены команды IC.TP с описанием:
- Роли и экспертизы
- GitHub аккаунт
- Текущие задачи и их статусы

### Боты (Bots)
Автоматизированные инструменты для поддержки процессов:
- **Страж (Guardian)** — мониторинг гигиены и качества репо
- **Вестник (Telegram)** — уведомления о событиях
- **Рефлектор** — диалог рефлексии через Telegram
- **Activity Tracker** — дашборд активности команды
- **Claude AI** — генерация кода и анализ

### Связность системы (Connectivity)
Метрика уровня организованности репо (0-100 шкала). Факторы:
- Документирование
- Управление знаниями
- Дисциплина разработки
- Качество автоматизации
- Code Review процесс
- Guardian нарушения

### Индекс зрелости (Maturity Index)
Оценка команды по 6 измерениям:
1. **Автоматизация** — CI/CD, workflows, Страж
2. **Документация** — Wiki, README, методология
3. **Командная работа** — синхронизация, ролевое разделение
4. **Управление знаниями** — обучение, онбординг, рефлексия
5. **Качество кода** — Code Review, тесты, архитектура
6. **Процессы** — методология, дисциплина, ритм разработки

## Статусы

### Статус задачи (Task Status)
- `in-progress` — идет активная работа
- `done` — завершено
- `blocked` — заблокировано (ждет зависимости)
- `discussion` — на обсуждении команды

### Статус Milestone
- `done` — завершен успешно
- `active` — текущий фокус
- `pending` — ждет очереди

## Фазы Стража (Guardian Phases)

- **Phase 1** — Гигиена файлов (структура, метаданные)
- **Phase 2** — Scope Monitor (мониторинг изменений)
- **Phase 3** — Semantic Rules (семантические правила)
- **Phase 4** — Smart Rules (адаптивные правила)
- **Phase 5** — Self-Healing (автоисправление)
